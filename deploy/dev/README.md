# Local E2E stack

`scripts/backend-dev.mjs`, used by Playwright's `webServer`, starts this Compose stack. It needs Node (the
version in `package.json`), Docker Compose and a backend binary built with `full,e2e-test-support`:

```sh
cd backend
cargo build --locked -p console-app --features full,e2e-test-support
cd ..
npx playwright test e2e/first-run-solo.spec.ts --project=parallel
```

Use `CONSOLE_APP_BIN=/path/to/console-app` to reuse a compatible binary. Install the repository's locked npm
packages and Playwright Chromium before running. No private checkout, Compose override or secret is needed.

The development tooling layer reuses only the existing E2E Postgres 18.4 and SeaweedFS 4.32 images, pinned by
digest. Postgres uses the same pin as the writer-ownership gate. SeaweedFS is required by registration-document
uploads (`e2e/entity-no-ocr.spec.ts`) and the solo journey's certificate/import steps. Mail is stubbed in process;
telemetry, ingress, mail servers and office services are outside this stack.

`e2e/slot.ts` owns ports and project names. Published ports bind only to loopback; each project has its own data
volumes. Credentials are generated by `scripts/dev-secrets.ts` in the ignored, mode-600 local secrets file;
JWT and vault keys are generated locally too. The Postgres init script provisions the existing migration,
runtime and command role contracts; migrations retain ownership of table grants and product authorization.
SeaweedFS requires the generated S3 credentials. Playwright resets only its own project's volumes on each run.

`npm run e2e:agent` reserves a slot for concurrent builders (see `scripts/e2e-agent.mjs` for its required environment).
Playwright stops its app servers; Compose data volumes remain until the next reset. Do not reset another
builder's project. `node --test scripts/e2e-stack.test.mjs` checks the public files, pins and service allow-list
without Docker. `npm run check` includes that regression gate.
