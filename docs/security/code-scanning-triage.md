After uploading each language's analysis, `scripts/check-codeql-diff.mjs` reads the same local SARIF and refuses security scores of 7.0 or greater (high/critical) whose primary location or reported data-flow step overlaps added lines. It compares the analyzed PR merge commit or merge-group commit with its event's base through their merge base. Existing findings outside changed lines, pure renames and deleted lines do not fail the diff gate. Missing/invalid scan evidence fails the job. Source and message text are not logged. GitHub also publishes its native [Code scanning results check](https://docs.github.com/en/code-security/how-tos/manage-security-alerts/manage-code-scanning-alerts/triage-alerts-in-pull-requests#managing-severity-levels-for-check-failures).

`Code scanning gate` is a stable, always-running aggregate: every scheduled language analysis and its applicable diff gate must succeed; failure, cancellation or skipped analysis fails it. The local gate needs neither an API token nor asynchronous result polling, so fork PRs use the ordinary read-only-token `pull_request` event. Full history is fetched for the merge-base comparison.

This also bounds repeated identifiers, roles and clearance keys, while preserving empty batches, index alignment and all-or-none persistence. The exact 2 MiB boundary is covered by a DB test. Refusals use `KernelError::with_code`; REST preserves that stable code and otherwise uses the shared error-kind code. These engineering limits belong to the resource-limit module and published API contract, independent of tenant policy.

The other reported runtime allocations already reject more than 20 goals, 10 evidence entries or 200 mobile operations, or clamp inbox page size to 1–200. Test-only dummy keys are retained as deterministic fixtures.

Absolute HTTP URLs are allowed only for loopback hosts (`127.0.0.1`, `::1`, `localhost`), preserving local presigned photo URLs. SVG/HTML data, active schemes, protocol-relative URLs and other HTTP hosts are refused. Every accepted URL, including a root-relative photo resolved against the browser origin, is returned from the parsed URL’s `href` after protocol/host checks.
